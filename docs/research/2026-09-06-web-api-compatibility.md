# Happy DOM extensions and npm toolchain research

Research date: 2026-09-06. Primary lane: **local-plus-external**, with OSS repository and recent-release verification.

## Executive Summary

The project implements a small Jest adapter over `@happy-dom/jest-environment` and a private, runner-independent compatibility workspace. This follows Jest's documented environment lifecycle and the working structure of `jest-fixed-jsdom`; the local integration tests exercise the installed environment rather than just calling installers in isolation. [Jest environment lifecycle](https://jestjs.io/docs/30.0/test-environment), [jest-fixed-jsdom implementation](https://github.com/mswjs/jest-fixed-jsdom/blob/main/index.js), [integration tests](../../packages/jest-happy-dom-extended/test/environment.test.ts).

Community reports and a fresh Happy DOM 20.14.0 probe justify extensions for structured cloning, broadcast messaging, binary Blob/File handling, Blob UTF-8 decoding, XHR constants, and composition input. Missing encoding/compression streams, MessageChannel, Blob.bytes(), and the ImageData VM failure were also reproduced locally. [Upstream probe](upstream-20.14.0-probe.log), [probe source](../../packages/compat/test/upstream-probe.ts), [regression tests](../../packages/compat/test/compatibility.test.ts).

The development compiler is stable TypeScript 7.0.2. The latest specified ESLint preset declares compatibility with TypeScript 6.0.3, so that version supplies the JavaScript compiler API used by lint/build tooling while a package alias invokes the TypeScript 7 compiler. This is an explicit compatibility arrangement, not a claim that the preset supports TypeScript 7's API. [TypeScript 7 metadata](https://registry.npmjs.org/typescript/7.0.2), [preset 5.0.0 peer dependencies](https://registry.npmjs.org/eslint-config-ts-prefixer/5.0.0), [compiler command](../../scripts/typecheck.mjs).

## What We Infer

- Sharing runner-independent installers and bundling them into each public adapter should let a later Vitest package reuse the fixes without depending on Jest. This is an architecture decision, not a tested Vitest compatibility claim. [Current shared entry](../../packages/compat/src/index.ts), [reserved Vitest workspace](../../packages/vitest-happy-dom-extended/README.md).
- A small environment adapter is preferable here to wholesale replacement of fetch/Blob/FormData: the reproduced FileReader boundary depends on retaining Happy DOM's Blob family. [#704](https://github.com/capricorn86/happy-dom/issues/704), [FileReader regression](../../packages/compat/test/compatibility.test.ts).
- Native channel and stream implementations give useful behavior beyond no-op stubs, but their Node semantics require explicit documentation and cleanup. [Node worker threads](https://nodejs.org/api/worker_threads.html), [package boundaries](../../packages/jest-happy-dom-extended/README.md#runtime-boundaries).

## Contradictions and Unknowns

- **Constructor presence was insufficient evidence.** The first inventory saw CompositionEvent as a function. The behavioral test then showed data was absent, and source inspection found the Event alias. The final implementation and decision table incorporate that correction. [probe](upstream-20.14.0-probe.log), [BrowserWindow source](https://github.com/capricorn86/happy-dom/blob/v20.14.0/packages/happy-dom/src/window/BrowserWindow.ts).
- **Older crypto failures were not reproduced on Node 24.20.0.** A VM-created ArrayBuffer was accepted by `crypto.subtle.importKey('raw', ..., {name: 'AES-GCM'})` in the current probe. This does not prove every algorithm or older Node release is fixed; no blanket crypto replacement was added. [#1924](https://github.com/capricorn86/happy-dom/issues/1924), [related Node report](https://github.com/nodejs/node/issues/55380).
- **An existing similar package is not a current drop-in answer.** jest-fixed-happy-dom 0.0.2 declares Happy DOM 17 compatibility and replaces Node globals broadly. That does not establish support for this repository's 20.14.0 behavior. [existing package manifest](https://github.com/maksnester/jest-fixed-happy-dom/blob/main/package.json), [existing implementation](https://github.com/maksnester/jest-fixed-happy-dom/blob/main/index.js).
- **Full browser conformance is not established.** Worker execution, idle scheduling, layout measurement, CORS state, and complete animation/canvas behavior require broader implementations or browser verification. Adding empty globals would not demonstrate those behaviors. [Happy DOM #2288](https://github.com/capricorn86/happy-dom/issues/2288), [official Canvas adapter](https://github.com/capricorn86/happy-dom/tree/master/packages/@happy-dom/node-canvas-adapter), [package runtime boundaries](../../packages/jest-happy-dom-extended/README.md#runtime-boundaries).
- **No standalone community issue was found for every added stream constructor.** For those APIs, evidence is the current runtime absence plus the official Node implementation and the package's behavior tests. [probe](upstream-20.14.0-probe.log), [Node Web Streams](https://nodejs.org/api/webstreams.html), [tests](../../packages/jest-happy-dom-extended/test/environment.test.ts).
- **TypeScript 7 documentation retrieval was incomplete.** The requested release-notes URL could not be fetched. Compiler availability and the preset's compatibility range were verified through official npm package metadata and local execution instead. [compiler metadata](https://registry.npmjs.org/typescript/7.0.2), [preset metadata](https://registry.npmjs.org/eslint-config-ts-prefixer/5.0.0).

## Confidence

**High** for the listed gaps on the recorded Happy DOM/Node version and their tested fixes. **Medium** for behavior on later Happy DOM releases until the regression suite runs against them. **Insufficient evidence** for a complete browser-compatible Worker/idle/layout implementation or a working Vitest adapter in this phase. [probe](upstream-20.14.0-probe.log), [tests](../../packages/compat/test/compatibility.test.ts), [Vitest workspace status](../../packages/vitest-happy-dom-extended/README.md).

## Actionable Next Steps

1. Run `pnpm check` for source checks, actual Jest integration, export/type validation, and a clean tarball consumer. [scripts](../../package.json).
2. Re-run `pnpm probe:upstream` when updating Happy DOM, then remove repairs whose upstream behavior and regression tests agree. [probe source](../../packages/compat/test/upstream-probe.ts).
3. Use Changesets for release preparation. GitHub hosting, npm ownership, and a registry publication are separate delivery steps, not evidence implied by the local setup. [release instructions](../../.changeset/README.md).
4. In the user-requested later Vitest phase, validate its current custom-environment lifecycle and pool semantics before implementing the reserved adapter. [reserved workspace](../../packages/vitest-happy-dom-extended/README.md).
